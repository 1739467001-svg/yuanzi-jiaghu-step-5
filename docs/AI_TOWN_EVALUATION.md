# AI Town 接入评估

评估时间：2026-09-22。参考提交：`8e05997f2409275669c8344b84a51692e83f3f33`（MIT，克隆在 `references/ai-town`，未安装其依赖、未运行其 Convex 服务）。背景：`docs/AI_TOWN_INTEGRATION.md`列出了接入前必须解决的问题，PRD 要求"先做双用户最小验证，再评估接入"。双用户与 AI 同房验证已于 2026-09-21/22 用自建服务端完成，本文给出结论。

## 1. 我们已自建的能力（对照上游）

| 能力 | AI Town 上游 | 原子江湖现状（自建） |
| --- | --- | --- |
| 权威位置 | `convex/aiTown/player.ts` | `server/world.mjs`：服务端校验目标、算路、10Hz 广播公开快照 |
| 移动与寻路 | `convex/aiTown/movement.ts` | 同一套 `engine.js` 寻路在服务端执行，客户端本地预测 + 温和收敛 |
| 会话 | `convex/aiTown/conversation.ts` | 一对一邀请/接受/拒绝/离开/屏蔽，服务端验证参与关系，私聊不进快照 |
| 身份 | `userStatus`/`joinWorld`（**鉴权被注释、使用 DEFAULT_NAME**） | `server/accounts.mjs`：注册/登录/scrypt/会话；hello 必须令牌，身份由服务端解析 |
| 记忆 | `convex/agent/memory.ts`（embedding + 向量检索） | `server/memories.mjs`：账号隔离、召回、删除传播、过期；可配置嵌入向量 |
| 引擎输入 | `insertInput.ts` | WS 命令通道（move/chat/profile/leave-queue） |
| 持久化 | Convex（托管实时数据库） | 本地 JSON 存储（账号/记忆/发布/审计/预算），生产可换数据库 |
| 前端表现 | Pixi 舞台 | Three.js 场景（保留，不替换） |

## 2. 接入 AI Town 现在要付出什么

1. **推倒已验证的世界服务端**：位置、会话、AI 运行时、重连/接管/排队均已在自建服务端通过六套 e2e 与 soak；迁移到 Convex 需要重做映射（`aiTownAdapter` 的坐标转换仅是样例测试，未经真实联调）与全部验收。
2. **先修上游鉴权**：`world.ts` 中真人鉴权被注释、身份使用 `DEFAULT_NAME`——直接复用等于回到"任何人可冒充任何人"的状态，与阶段 7 已关闭的漏洞相同。
3. **地图重导**：上游寻路格需与当前 6 建筑、河流、双桥、展馆完全一致，任何偏差都会破坏 A02 导航验收。
4. **持续成本**：Convex 账户与配额、双套后端并行期的行为不一致风险。

## 3. 结论与建议

**建议：不迁移，继续使用自建服务端。** 理由：AI Town 对 P0 的独特价值（Convex 托管实时数据库、其 Agent 记忆框架）在本产品的规模（单房间 20 人、8 位 AI、本地演示部署）下不构成瓶颈；而迁移成本是重做全部已验收项并重新打开已关闭的安全问题。PRD 的"固定版本作为接入起点"应理解为**参考其数据模型与接入点**（已在 `AI_TOWN_INTEGRATION.md` 完成对照），而非替换后端。

**重新评估的触发条件**（满足其一再立项）：
- 需要跨多进程/多机的水平扩展（当前单进程单房间→多房间已支持，再上是分片问题）；
- 需要托管实时数据库与自带运维（备份、多区域）；
- 需要上游 Agent 框架的自主规划能力（我们目前用服务端状态机 + 可配模型大脑，PRD G3 的"AI 自主推理日程"若升级为自主规划再评估）。

**若将来要接入，推荐增量路径**（不做大爆炸替换）：
1. 保持现有 WS/HTTP 契约与前端不变；
2. 仅在存储层引入 Convex：为 `accounts`、`memories`、`publication`、`budget` 实现同一接口的 Convex 适配器（存储接口已按文件隔离，替换点是 `server/*.mjs` 的读写函数）；
3. 身份与鉴权继续用本项目的账号体系，不启用上游 DEFAULT_NAME 路径；
4. 每替换一个存储跑一遍对应 e2e 再切换。

## 4. 上游可继续借鉴的点

- `convex/agent/memory.ts` 的重要性/摘要字段设计——我们记忆条目的 `kind`/`source` 可参考扩充；
- 心跳世界（heartbeatWorld）的无人降频思路——已按 PRD 15.2 以"无人休眠"实现；
- 其 AGENTS 数据结构（技能、兴趣、说话风格）与 `config.js` 的角色设定字段已对齐。
