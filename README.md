# 原子江湖 · AtomHub Living World

原子公社的可运行 3D 社区原型。白蓝斗笠侠客、青瓦茶楼、共创工坊、开源书院、石桥与比赛展示馆共同构成第一张地图。

## 在线演示与 GitHub

- 仓库：https://github.com/1739467001-svg/Atomic-Jianghu
- 在线 3D 演示：https://1739467001-svg.github.io/Atomic-Jianghu/

推送 main 后，GitHub Actions 自动测试、构建并部署 GitHub Pages。线上使用浏览器内的资料检索与演示对话，不提供模型代理或云端数据存储。作品、3D 小镇、收藏与授权记忆均可使用。

手动构建同样的静态版：`VITE_BASE_PATH=/Atomic-Jianghu/ VITE_STATIC_DEMO=true npm run build`。部署产物是 dist；本地开发不设这两个变量即可继续使用 Vite 提供的 API。

## 启动

需要 Node.js 22.12+。

```bash
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。也可以双击 `启动原子江湖.command`（5173 被占用时会自动改用空闲端口）。

> npm 11.3+ 默认阻止依赖的安装脚本；esbuild 与 fsevents 的安装脚本已在 `package.json` 的 `allowScripts` 字段中批准，`npm ci` 无告警。若看到 `install scripts not yet covered by allowScripts` 提示，按 docs/DEPLOY.md 第 11 节排障表处理。

**部署到服务器（Docker，推荐）**：`cp .env.example .env` 后 `docker compose up -d --build`，一条命令在任何云服务器跑起完整联机体验——含账号、权威世界、AI 私聊与运营后台；有域名时加 `--profile tls` 自动 HTTPS（Caddy）。数据落命名卷，容器重建不丢。镜像要点、升级回滚与排障见 [docs/DEPLOY.md](docs/DEPLOY.md) 第 11 节。不用 Docker 时也可 `npm run build && npm start`（默认 `0.0.0.0:8080`）。

**部署到 Vercel（前端静态托管 + 世界服务端分离）**：权威世界需要长驻进程与 WebSocket，Vercel 的 serverless 模型不支持，因此采用前后端分离——仓库已含 `vercel.json`（导入即用，构建 `npm run build`、输出 `dist/`）；世界服务端用 `docker compose up -d --build` 或任意 Node 主机部署，前端构建时设 `VITE_API_BASE=https://<服务端域名>` 与 `VITE_WS_URL=wss://<服务端域名>/ws/world`，服务端设 `ATOM_ALLOWED_ORIGINS=https://<前端域名>` 放行跨源。完整步骤与排障见 [docs/DEPLOY.md](docs/DEPLOY.md) 第 10 节。
```bash
npm test
npm run validate:world
npm run build
npm run preview
```

`dev` 和 `preview` 都包含本地聊天接口；只把 `dist` 放到静态主机不会提供聊天 API。`dev/preview` 监听回环地址适合本地评审；公开部署用 `npm start`（见 docs/DEPLOY.md）。

## 浏览器验证

启动本地服务后执行 `npm run test:e2e`。默认使用已安装的 Google Chrome；自动检查桌面、390px 手机布局（含底部抽屉展开/收起）、834px 平板无横向溢出、作品深链接、记忆删除与 WebGL 降级，并将截图写入忽略版本管理的 `artifacts/`。

长时压测：`npm run soak`（默认 5 分钟）、`npm run soak:long`（2 小时 / 24 玩家）、`npm run soak:72h`（72 小时口径，建议在专用机器上运行；报告每 30 秒增量写入 `artifacts/soak-report.json`，中途崩溃不丢数据）。模拟玩家会随机移动、邀请私聊、断线重连，并周期性到茶楼入座、坐一会儿、起身、邀请同桌；脚本同时校验座位不变量（同座不双占、就座位置锁定、入座拒绝原因合法）。两小时轮实测：646 次入座 / 556 次起身 / 369 次同桌相邀、座位不变量零违例、快照 p95 107ms、零页面错误（详见 `docs/VERIFICATION.md`）。服务端另有未认证连接 15 秒超时保护（只连不 hello 的连接会被回收）。

`npm run test:e2e-mp` 是联机世界双浏览器验收：双账号互见与位置一致、茶楼两人同桌共坐互见（占用显示昵称、起身释放座位）、AI 侠客也会落座茶楼（占用公开、不可抢座）、同桌一键相邀（坐着聊）、邀请/接受/私聊、第三方只看到"交谈中"、离开通知、同账号接管（可用 `TEST_BASE_URL` 指定端口）。

`node scripts/shots-v2.mjs` 与 `node scripts/shots-online.mjs` 是人工验收脚本：前者等待 AI 侠客完成观展并截取观展气泡、品牌关于页与聊天观展见闻；后者截取联机双账号画面、邀请弹窗与私聊面板。均需要服务已在运行。

## 已实现

- Three.js 真实几何场景、可旋转缩放镜头、点击移动、建筑碰撞与过桥路径。
- **联机世界（v2 阶段 4—7、18）**：顶栏切换到"联机世界"即接入服务端权威房间（WebSocket）。进入前需要账号——默认本地"侠客名帖"（scrypt 加盐、会话持久化）；生产可切外部身份（`ATOM_AUTH_MODE=external`，JWKS/内省验证社区账号令牌，subject 稳定映射）——hello 必须携带服务端会话令牌，角色 ID 由服务端从会话解析，客户端传入的身份一律无效（禁止冒充他人接管）。服务端校验可走区域与目标、计算路径、以约 10Hz 广播公开快照；客户端本地预测点击移动、温和收敛到服务端位置。两个浏览器账号看到一致的公开位置，可邀请一对一私聊（内容只送达两人，世界快照只显示"交谈中"），可屏蔽；断线 60 秒内可用原身份重连续场；同账号第二个标签页明确接管旧控制会话；房间容量 20（`ATOM_ROOM_CAPACITY` 可配），满员时进入 FIFO 排队队列——看到自己的位置、有空位自动进入、可随时取消；断线后 15 秒内名额保留给重连（`ATOM_RECLAIM_WINDOW_MS` 可配）。
- **联机社交可视化（v2 阶段 20）**：私聊中的玩家头顶显示"交谈中"气泡（内容不可见，符合 PRD 旁观规则）；表情栏可发送公开表情招呼（打招呼/作揖/鼓掌/思考），附近玩家头顶可见 3 秒（服务端限速）。
- **茶楼共坐（v2 阶段 24）**：茶楼设两桌六座，走到茶楼附近即可在面板选空位入座——全房间可见谁坐了哪桌哪席（占用显示昵称），入座后位置由服务端锁定（移动被拒绝并提示先起身，站着的人不会"穿过"桌子），坐着也能私聊，随时起身释放座位；断线自动离座。
- **茶楼常有 AI 侠客落座（v2 阶段 25）**：AI 侠客的日程走到茶楼后也会找个空位坐下——坐着歇脚、坐着被邀请闲聊（私聊中保持坐姿），全房间在座位面板与 3D 场景里都能看到谁坐了哪桌哪席；AI 一有行程就起身离开，座位释放；真人不能坐 AI 占着的座位，正走到座前时 AI 也会避让。茶楼是社交中枢，全天时辰都可能有侠客落座。
- **茶桌同桌（v2 阶段 26）**：入座后面板直接列出同桌的人（AI 与真人，含"交谈中"状态），一键"请他闲聊/邀请私聊"——坐着就能把天聊上；入座、离座与 AI 落座都会进入"江湖此刻"活动流，茶楼的聚散对全房间可见。
- **多房间分流（v2 阶段 13）**：可用 `ATOM_ROOMS=id:名称:容量,...` 增加房间；每个房间是独立的权威世界（位置、私聊、AI 侠客互不串通），侧栏"江湖客栈"显示各房间占用并可切换；同一账号同时只在一个房间（切换时旧房间连接被踢出）；`GET /api/rooms` 公开占用统计。联机模式与本地演示模式互斥。详见 `docs/NEXT_TASK_PLAN.md` 阶段 4—7。
- **AI 侠客同居联机世界（v2 阶段 5）**：八位 AI 侠客作为服务端角色与真人同房间生活——按时辰移动、两两社交、观展并形成有来源的观感；真人可邀请任意 AI 一对一私聊，第三方只看到"交谈中"。无人时世界休眠，首位真人进入时恢复。详见 `docs/NEXT_TASK_PLAN.md` 阶段 4—5。
- **联机 AI 模型对话与持久预算（v2 阶段 6）**：配置模型后，联机世界里与 AI 侠客的私聊走真实模型（人设 + 已发布作品 + 亲身观感注入，界面标注"模型对话"）；持久账本按 requestId 去重、并发预留、日预算 80%/100% 降级，重启不清空；未配置、失败或超额时回退本地资料检索并如实标注。
- 八位虚构 AI 侠客的本地活动状态机：按时辰偏好前往建筑、歇脚、两两社交、记录公共见闻；私人交谈可打断活动。
- **AI 观展闭环（v2）**：侠客按兴趣计划观展，走到展示馆后读取已发布作品的结构化事实，生成不超过 60 字、明确属于个人看法的观感，记入公开见闻；同一角色对同一作品只生成一次。观展中的侠客头顶浮现所看书名气泡，闲聊话题也会引用观展见闻。
- **聊天中的观展回忆（v2）**：询问"你今天在馆里看了什么？"，侠客只谈自己真正看过、来源是已发布资料的作品，并附上可打开的作品卡片；推荐回答会带上他自己的观感。配置真实模型后，观展见闻作为角色的亲身经历进入服务端上下文。
- 原创 IP 参考的程序化角色：黑斗笠、白衣、蓝衣带、脸颊、佩剑；可改昵称与衣带颜色。
- **GLB 资产接入（v2 阶段 10）**：角色模型可整体替换——GLB 放进 `public/models/` 并在 `src/world/config.js` 的 `MODELS` 清单登记即可，带动画的按 idle/walk 播放、无动画使用根节点兜底动画；加载失败自动回退程序化，不阻断场景。当前内置从程序化角色导出的示例基线，接入指南见 `docs/MODELS.md`。
- 品牌元素：官方 Logo（原子公社 + 父品牌原子之心 Atomesh）、原创 IP 欢迎图、社区表情包墙；品牌依据为《原子公社对外介绍 v2.2》。
- 日夜切换、四套环境配色。主题切换目前只改变配色；建筑位置可在 `src/world/config.js` 编辑，未提供拖拽地图编辑器。
- 可进入的独立 3D 展厅：八位 AI 侠客也在馆内——在展位间行走、在展位前驻足观展并浮现书名气泡，可点击发起聊天；展厅展示房间固定的共享展陈展区（当前 FunSkills 38 条、5 个展区）；完整目录可访问繁星之夜 38 条、数智星光展 18 条与星火计划赛事介绍（主办方、两阶段赛程、奖项设置来自参赛手册），共 56 条作品记录。
- **首访引导（v2 阶段 19）**：首次进入显示三步引导（移动、看展、区分真人与 AI），可跳过且仅出现一次。
- **小镇导览（v2 阶段 21）**：侧栏一键开始脚本化游览——品牌介绍 → 茶楼 → 工坊 → 书院 → 星火亭 → 展示馆，每站有解说卡，角色自动前往、相机跟随，可回退、可随时结束，收尾可直接入馆。
- 赛事切换、赛道筛选、作品/作者搜索、高清海报、收藏、最近浏览、稳定的 `?work=赛事--slug` 分享链接。
- 本地资料检索向导；可选 OpenAI 兼容模型接口。
- **私人记忆（v2 阶段 8、11）**：兴趣记忆保存在账号里（服务端），按 (账号, 角色) 隔离、仅本人可见；用户主动开启并主动表达兴趣时才保存，可逐条或全部删除——删除后立即不再被召回（召回先限定作用域），并递增版本号丢弃在途结果；支持过期时间；聊天上下文（本地检索与模型大脑）由服务端按账号读取记忆，不信任客户端提交的内容。登录时若检测到本机旧记忆，提供"迁移到账号 / 保留在本机"的明确选择。召回排序默认用字符二元组 TF-IDF 余弦 + 新近度（中文免分词，"喜欢/我在"等普通词按作用域内文档频率降权）；配置 `ATOM_EMBEDDING_*` 嵌入提供方后，记忆召回与作品检索自动切换为**向量余弦相似度**（按文本哈希缓存，未配置或提供方故障时自动回退 TF-IDF，行为不变）；A08 口径（20 授权案例 ≥18 正确召回、10 无记录案例零伪造）已有自动化验收。
- **多终端适配（v2 阶段 27）**：手机（≤650px）侧栏改为可展开的底部抽屉——折叠只露 IP、标题与主按钮，展开显示完整侧栏（江湖此刻/遇见同行侠客/关注）；横屏手机与矮屏专用压缩；工具条触控目标放大、隐藏鼠标专属提示；新手引导层级置于抽屉之上不再被挡。平板与桌面保持三栏布局。390/360/834/1024/1280/1440 六档视口均有截图与自动化断言（无横向溢出、抽屉展开收起、作品网格双列）。
- 手机布局、键盘对话框焦点约束、无 WebGL 时的作品目录入口。
- **关注（v2 阶段 22）**：单向关注/取消关注，真人与 AI 熟悉度分开存储、按账号隔离；联机名帖与"同行侠客"面板可关注，手札"我的关注"页统一管理（联机时显示真人是否在线）。
- 私人聊天（与 AI 侠客）需要登录名帖（PRD 4.1：游客不发送私聊）；本地漫游、看展、搜索、分享不需要登录。

## 模型配置（可选）

将 `.env.example` 复制为 `.env.local`，填写模型服务地址、模型名和密钥，然后重启服务。不要把密钥放在 `VITE_` 变量或提交到 Git。

未配置时，界面明确显示“本地资料演示”，回答来自检索和预设话术。它不是已连接语言模型的自主智能体。配置后，本地演示模式的私人对话与联机世界里与 AI 侠客的私聊都走真实模型（人设 + 已发布作品 + 角色亲身观感作为不可信资料注入）；AI 间的日常社交仍是本地状态机演示。

**持久预算**（随首次模型接入一起落地）：模型调用按 requestId 去重、并发先预留后结算，账本落盘 `data/usage-ledger.json`，服务重启不清空费用。每日预算 `ATOM_DAILY_BUDGET` 达到 80% 进入 warn，达到 100% 暂停新模型调用并改用本地资料如实说明（看展与真人聊天不受影响）；`ATOM_DAILY_CALL_LIMIT` 限制每日次数，单价按 `ATOM_PRICE_*_PER_MTOK` 配置。接口设置 20 秒超时；模型失败时回退本地检索并标注。

## 运维可见性

`/api/ops`（管理令牌）与运营后台“运行状态”页签：房间占用（在线/等待/容量）、模型配置与今日费用/预算档位/并发、进程 uptime 与内存，每 5 秒自动刷新——部署后一屏掌握运行状态。

## 运营后台（本地演示）

打开 http://127.0.0.1:5173/admin.html ，输入本地运营令牌（未配置 `ATOM_ADMIN_TOKEN` 时默认为 `atom-local-demo`）。

- **赛事管理**：发布检查（必填字段、唯一标识、媒体可读、私人字段）、发布/撤回一届赛事、按审计事件回滚。
- **作品管理**：搜索与筛选后发布/撤回单件作品；后台看到全部状态（含草稿与已撤回），公开目录只返回已发布。
- **审计日志**：每次发布、撤回、回滚都留下不可删除的记录（操作者、前后状态、时间）。
- **导入检查**：读取来源展示站数据，dry-run 报告新增/更新/缺失差异，不写任何状态。

发布状态写在覆盖层 `data/publication-overrides.json`，`src/data/editions.json` 保持不可变基线。撤回后公开详情返回 410，目录、3D 展位、AI 观展目标与检索一致更新（前端 15 秒内自动刷新）。这是本地演示的写入层，不是生产权限系统；接口请求需带 `x-atom-admin` 头。详见 `docs/NEXT_TASK_PLAN.md` 阶段 3。

## 内容与共享展陈

赛事、赛道与作品统一走 `src/content/catalog.js` 与发布状态存储：公开读取只返回 `publicationStatus` 为“已发布”的内容，草稿与已撤回不进入任何入口。3D 展厅、阅读目录、演示导览和内容接口读同一份实时数据。

3D 展厅展示房间固定的共享展陈展区 1（`src/content/exhibition.js`，当前为 FunSkills 38 条、5 个展区）；阅读面板的个人筛选只改变面板列表，用“展陈中”标记与展区编号区分。接口失败时前端降级到内置快照并提示，作品阅读不中断。详见 `docs/CONTENT_SERVICE.md`。
