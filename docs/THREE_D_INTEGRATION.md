# 3D 视觉模拟 × 平台对接地图

> 2026-10-17。配套文档：[OFFICIAL-SITE.md](OFFICIAL-SITE.md)（官网调研）、[SECTS.md](SECTS.md)（门派接入契约）。
> 本文回答一个问题：**我们这座 3D 小镇，有哪些东西可以和原子公社平台对接、怎么接、现在到哪一步了。**

---

## 产品定位：官网的 3D 线上互动平台

**一句话**：原子江湖是原子公社官网的 3D 线上互动平台——官网负责"登记与发现"（账号、活动、门派、经济的权威数据），3D 小镇负责"走进来"（把社区的内容、关系与 AI 伙伴变成可以走进去的空间），最终把访客引荐给官网、加入开源社区。

**分工边界**（对齐官网实际架构，见 OFFICIAL-SITE.md）：

| 层 | 属于谁 | 内容 |
| --- | --- | --- |
| 数据与关系 | 官网（权威） | 账号、活动、门派、茶楼帖子、原子币账本 |
| 立体呈现与共处 | 3D 小镇 | 门派大殿/聚义阁、展示馆、茶楼、论剑台、AI 侠客、联机世界 |
| 身份与经济 | 官网（权威），3D 只读展示 | 登录、报名、签到、兑换 |

**用户旅程**（3D 平台的存在理由）：

1. **吸引**——官网链接/分享进来，看到一座有 AI 侠客在生活的活小镇，而不是又一张 landing page；
2. **引导**——和 AI 侠客聊官网真实活动（"最近有什么黑客松？"）、走进展示馆看社区真实赛事、进门派大殿看真实门派；
3. **转化**——欢迎卡的「加入原子公社」、关于页的官网入口组、活动页的官网链接、门派大厅的回跳——每一层都有明确的官网出口，把兴趣变成注册与加入。

**本轮已落地**（2026-10-17）：① 官网 6 个真实门派进 3D 大殿（含封面）；② 官网 350 场活动进展示馆赛事目录（ organizers/赛程/奖项全部线上真实数据，经后台导入闭环）；③ 欢迎卡与关于页的引流 CTA（`VITE_SITE_URL` 可配，默认 atomclub.cn）；④ 关于页过期文案修正（联机/账号/后台早已就绪，原文还说"尚未接入"）。

## 0. 先想清楚：3D 小镇对平台的价值是什么

官网是二维的：列表、帖子、按钮。3D 小镇能提供的是官网给不了的四样东西——

1. **空间记忆**：门派不再是一个卡片，是河畔一座能走进去的牌坊；活动不再是表格里一行，是展示馆里可以站在它面前的一件展品。人对空间的记忆远强于对列表的记忆。
2. **共处感**：八位 AI 侠客在镇里生活（看展、喝茶、论剑），真人联机进入后是"来到一个有人在的地方"，不是"打开一个网页"。
3. **关系的具身化**：关注、同门、邀请——官网上是数字和名字，在 3D 里是"谁坐在你旁边喝茶"。
4. **内容的停留时长**：二维信息流是滑过，3D 展品是走到、驻足、点击、听 AI 侠客聊它——每一次驻足都是一次内容消费。

所以对接的原则是：**平台出数据与关系，3D 出空间与共处**。不把官网照搬进 3D，而是把平台上"值得被看见"的内容变成"值得走进去"的地方。

## 2. 已打通的两个深度案例

### 2.1 门派：从演示数据到官网真实社区（本轮完成）

**契约映射**（官网字段 → 我们的字段，`server/sects-source.mjs`）：

| 官网 | 我们 | 说明 |
| --- | --- | --- |
| `id/name/slogan/intro` | 同名 | 直接命中 |
| `joinType`（open/apply/invite） | `joinPolicy` | 同值域不同名，已加别名映射 |
| `coverUrl` / `logo` / `tags` / `memberCount` / `activity` / `score` | 透传 | 3D 牌坊挂封面、面板显示标签与成员数 |
| `leader/founder`、`elders/council`、`members` | 已有别名 | 三角色按称号分堆 |

**封面代理**（`server/cover-proxy.mjs` + `GET /api/sects/cover`）：官网封面在阿里云 OSS，不回 CORS 头，浏览器直接加载会被拒。同源代理把图抓过来再发前端；安全边界是**只放行当前远程快照里出现过的图片主机 + 数据源主机**（不是开放代理，防 SSRF），带内存缓存与体积上限；抓取失败回 404，前端撤掉封面布——牌坊保持完整，封面是增量不是依赖。

**3D 呈现**：大殿里每座牌坊正面挂官网封面图，进入内景后主位后墙挂封面幔；左侧名录显示 tags 与加入方式。

**实测**（2026-10-17）：`ATOM_SECTS_SOURCE=https://atomclub.cn/api` 起服务，同步到 6 个真实门派（原子公社、耶烨烨、带派、上海未来启点社区……），`joinType` 映射正确（open/apply 都对），封面经代理正常渲染（307×305 PNG，122KB），零页面报错。截图 `artifacts/official-sects-hall.png`。

**接法**（一行配置）：`ATOM_SECTS_SOURCE=https://atomclub.cn/api`，其余（TTL、失败保留快照、冷启动缓存兜底、本地覆盖层）全部既有能力。

### 2.2 模型：AI 侠客接上原子引擎

`ATOM_LLM_BASE_URL=https://atengin.atomclub.cn/v1` + `ATOM_LLM_API_KEY=<Key>`，AI 私聊即走真实模型（人设 + 已发布作品 + 亲身观感注入，界面标注"模型对话"）；持久预算账本按 requestId 去重、日预算 80%/100% 降级，未配置/失败/超额自动回退本地检索并如实说明。嵌入向量同理（`ATOM_EMBEDDING_*` → 引擎 `/v1/embeddings`），记忆召回与作品检索切换语义向量。**建议先用 `npm run test:e2e-model`（本地 mock）验证通道，再填真实 Key。**

## 3. 可打通项的设计思路

### 3.1 官网活动 → 3D 展示馆（最自然的延伸）

官网有 350 场真实活动（技术沙龙 178 / 黑客松 59 / 创业大赛 27 / OPC 大赛 12……），字段齐全（类型、时间、地点、主办方、报名数、简介）——**唯一缺的是海报图**。两个方案：

- **方案 A（零媒体依赖，推荐先做）**：照「星火计划」的形态加一个「原子公社 · 社区活动」赛事页——organizers/schedule/benefits 全部来自 `/api/events/stats` + `/api/events/types` 真实数据，作品区保持"资料核对前不展示"（与现有口径一致）。目录里多一个真实赛事页签，3D 展示馆多一块可看的介绍区。
- **方案 B（活动变展位）**：每场活动生成一个程序化"活动碑"（类型着色 + 日期 + 地点 + 报名状态的 3D 牌子），走进展示馆像走进一条活动长廊。无图但不空。

数据流两种都走既有闭环：`scripts/fetch-official-events.mjs` 抓取 → 生成导入载荷 → 运营后台「赛事导入」预检 → 确认导入 → 发布。全程不改代码、留痕可回滚。

### 3.2 热帖与资讯 → 江湖此刻与头顶气泡

加一个服务端模块 `official-feed.mjs`：TTL 抓取 `/api/teahouse/posts/hot` + `/api/news`，失败沿用上次快照（与门派同步同款降级）。用途：

- **AI 侠客的社交话题**引用真实帖子标题（"聊起了社区里那篇《a16z 最新 90 页报告》"）——闲聊从此有真实内容可聊；
- **英雄帖墙**贴社区热帖（论剑台旁边那面悬赏墙，数据接口就绪后替换示范条目）；
- **江湖此刻**混入官网资讯源。

### 3.3 原子币与经济 → 3D 钱庄、签到台、商店

官网已有完整经济：原子币、钱包流水、每日签到（+20 币）、商店（帆布袋 1888 币）、任务成就。3D 化设计：

- **签到台**（小镇广场）：每日签到按钮，奖励实时显示——天然互动，无需等身份打通也能先做"展示态"；
- **3D 商店**（工坊旁）：官网周边按原子币定价陈列，点击看大图（封面代理同款管线）；
- **权益碑扩展**：把官网商店与任务列表刻上碑——"权益待接入"变成"权益实时可读"。

前提是 #6（账本对账接口）与 #7（身份）——**展示态可以先做，交易态等接口**。

### 3.4 身份打通后的想象（阻塞项解除后）

- 官网账号 = 联机世界身份：名帖、头像、等级（初入江湖……）自动同步，注册那一步直接消失；
- **活动足迹**（官网有 `/api/user/event-traces`）：参加过的活动在 3D 里变成"你去过的地方"；
- **关注关系**：关注的侠客在线状态显示在"遇见同行侠客"里；
- **报名/签到回写**：在 3D 展示馆里看完一场活动，直接报名。

## 5. 风险与边界

- **外网依赖**：官网/引擎不可用时，门派同步失败保留上次快照（大殿照常开门）、内容接口降级本地快照、模型回退本地检索——三条降级链都已就绪，但要在文档和监控里让运维知道"现在显示的是快照"。
- **封面代理的安全边界**：主机白名单只认远程快照里出现过的图片主机；换图床时名单自动跟着变，不放开。
- **内容时效**：门派 TTL 默认 5 分钟、资讯抓取建议 10—15 分钟；都走"失败沿用旧值"，不闪空。
- **不承诺官方没有的能力**：报名回写、账本结算、身份签发——在官方确认前，3D 里只做展示态，界面明确标注数据来源与延迟。
